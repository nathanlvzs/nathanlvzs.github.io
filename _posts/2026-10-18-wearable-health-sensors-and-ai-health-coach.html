序：一句话讲清这件事的本质

所有消费级健康穿戴设备做的事情，本质上都是同一件事：

用一束光、一枚电极、一颗加速度计，去反演（inverse problem）人体内部那些本来需要 CT、抽血、多导睡眠监测才能看到的生理过程。

这句话有三个隐藏含义，理解它比记住任何一个硬件参数都重要：

  1. 穿戴设备几乎从不「直接测量」目标量。 它测量的是一个代理量（proxy），再用模型把代理量映射成你想要的数字。血压就是最典型的例子：手表从未测过血压，它测的是脉搏波传播速度/形态，再用一条标定曲线把它翻译成 mmHg。
  2. 代理关系的稳定性决定了这个产品的天花板。 而这个关系会被血流灌注、肤色、体毛、佩戴松紧、体温、姿势、水合状态、药物共同扰动。
  3. 因此，AI 健康教练 Agent 的第一性原则不是「多准」，而是「知道什么时候不可信」。 一个能对自己输出的置信度诚实的 Agent，价值远高于一个把估算值吹成检测值的 Agent。

第一章 传感器篇：手上这几颗脏器件到底在测什么

1.1 先建立一个分类直觉

穿戴里的传感器可以按「它感知的是哪种物理量」分成七大类。这个分类不是学术洁癖——每一类对应一套完全不同的误差来源和算法处理方式，混淆它们是新手最常见的错误。

1.2 光学：PPG 是整个行业的地基

硬件长什么样

一个典型的反射式 PPG 模组包含：

  • 发光端：若干 LED。主流是绿光（~525nm）、红光（~660nm）、红外（~850nm 或 ~940nm）。高端方案追加黄光（~590nm）、甚至蓝/紫光，用来探测更深或更浅的组织层——因为波长越长，穿透越深：
  • 绿光：穿透浅（~1–2mm），主要被真皮层毛细血管丛感知，血流灌注变化引起的交流成分（AC）幅度大，所以最适合测心率；但受运动伪影影响最大。
  • 红光/红外：穿透深（可达 5–10mm），能到达小动脉层，主要用于 SpO₂（因为血红蛋白在这两个波长上的吸收差异最显著）。
  • 接收端：光电二极管（PD），把返回光强转成电流。
  • 前端：AFE（模拟前端，如 ADI、TI、汇顶、天易合芯方案）负责 LED 驱动、跨阻放大、环境光抵消、ADC。
  • 辅助：加速度计几乎是 PPG 的法定搭档，原因见 §3.2。

为什么戒指比手表更容易测得准（这是个真问题）

这不是玄学。手指腹/指根的动脉密度高、毛细血管丛丰富、组织厚度薄、环形结构的稳定贴合也有助于形成稳定光路；而手腕有桡动脉+尺动脉双重路径、骨骼与肌腱多、且极易在运动中产生传感器位移。同一颗 sensor，戴手指上的 SNR（信噪比）通常可能高于手腕。 代价是：典型戒指通常不提供 ECG（难以形成心电回路），也放不下 ECG 电极与更大的电池。

Oura Ring 4 是目前把这条路线走到极致的产品：采用厂商称为 18-path multi-wavelength PPG 的 Smart Sensing，按佩戴条件选择 LED，以兼顾信号质量与功耗。厂商报告的相对上一代改进包括血氧信号质量、夜间平均 SpO₂ 准确度及心率图缺口；这些是特定研究条件下的厂商结果，不能外推为通用临床准确度。Oura 的方法与限定条件这套「用算法换信噪比、用信噪比换功耗」的思路，是所有穿戴信号链的通用范式。

光学传感器演进的三种典型方向

  1. 多通道 & 多光路选择：一个发射多个接收，或反过来；动态选路（Oura Smart Sensing），本质是在时变的物理接触条件下做自适应采样。
  2. 多波长光谱：从 3 波长扩展到 5–8 波长，目标是把「只看血流」升级为「看血的成分」——这是无创血糖、无创乳酸、血红蛋白、甚至类胡萝卜素（三星 Galaxy Watch8 的 Antioxidant Index 就走反射光谱路线）的物理前提。
  3. 换测量部位：耳朵（AirPods Pro 3）、前额、锁骨下、上臂。耳道的好处是灌注好、几乎无环境光泄漏、相对稳定；代价是极端情况下 颅面/耳道几何差异巨大，所以苹果说他们测试了数千参与者的耳道几何与肤色来找最优传感器位置。

1.3 电学：ECG 与生物阻抗

单导联 ECG

结构上就是两个（或三个）电极：

  • 手表背面电极（贴手腕）
  • 表冠/边框电极（另一只手手指按住）

这样就形成了一条近似 Lead I 的回路（左手腕 → 右手手指），可以记录 30 秒的单通道心电。它的价值在于：这是穿戴里唯一「直接测量」而非代理测量的生理信号之一——心电是心脏电活动的直接表达，不像血压/血糖是反演出来的。所以它的 FDA 性能可以做到很高（Apple ECG 1.0 临床研究中，算法对 AFib 的灵敏度/特异度均在 98%+/99% 量级）。

局限也一眼可见：单视角。医院是 12 导联，从不同角度「拍照」心脏；手表只有 1 个角度。它能可靠回答「节律规不规整」，无法回答心电图医生关心的很多问题（如 ST 段缺血形态、轴偏、大多数传导异常）。

一个常被忽略的工程事实：ECG 需要用户主动配合（手指按住表冠 30 秒且保持静止），所以它是按需式（episodic）而非连续式的。这与 PPG 的机会式 opportunistic 连续监测形成互补——行业已经形成了稳定的两级架构：

PPG 连续/机会式 粗筛  ──►  可疑  ──►  ECG 按需 确认  ──►  就医/贴片进一步确诊

这是穿戴健康最重要的架构模式，做 Agent 时必须理解：你的信号源天然是「低成本低保真 + 高成本高保真」的两级体系，而不是单一数据源。

生物阻抗 Bio-Z / BIA

原理：向组织注入一段微弱、高频（通常 5kHz–200kHz 多频）交流电，测量两点间的阻抗 Z 与相位角 \theta。

物理基础： - 细胞内/外液是良导体（电解质溶液），细胞膜是电容器，脂肪几乎绝缘。 - 低频电流主要走细胞外液，高频电流能穿透细胞膜走细胞内液 —— 这是多频 BIA 能区分细胞内液/外液的原理。 - 经验模型（Cole-Cole 模型）把 Z(f) 拟合为：Z = R_\infty + \frac{R_0 - R_\infty}{1 + (j\omega\tau)^{1-\alpha}}

可推出的东西： - 体成分：结合身高体重与阻抗指数 H^2/R，用回归估算去脂体重 → 脂肪率 → 肌肉量。八电极体脂秤精度尚可，手表/戒指的局部测量（手到手）误差明显更大。 - 水合状态 / 体液潴留：这对心衰监测特别有价值（胸腔积液 → 阻抗下降）。 - 呼吸率：胸腔容积变化 → 跨胸阻抗变化（约 0.1–1Ω），这是医院呼吸监护的标准方法之一。手表上很难实现，因为电流路径不经过胸腔。 - EDA / 皮肤电：汗腺活动改变皮肤导电性 → 交感神经兴奋的窗口这是理解 EDA 的关键：EDA 测的是交感唤醒（arousal），不是情绪效价（valence）。害怕、兴奋、愤怒、运动前的紧张，EDA 都长一个样。很多「AI 情绪手表」在这里犯严重的解释错误。

1.4 化学：CGM 是目前唯一成熟的「分子级」穿戴

原理（务必搞清楚，因为它定义了「连续」的含义）

  1. 一根比头发丝略粗的柔性电极丝植入皮下（真皮层深处，通常是上臂或腹部），停留在组织间液（interstitial fluid）中。
  2. 电极丝尖端固定着葡萄糖氧化酶（GOx）。
  3. 葡萄糖扩散进来：葡萄糖 + O_2 \xrightarrow{GOx} 葡萄糖酸 + H_2O_2
  4. 工作电极检测 H_2O_2 氧化产生的电流，或通过氧化还原介体传递电子 → 电流大小 ∝ 葡萄糖浓度。
  5. 每 1–5 分钟采样一次，蓝牙发给手机。

关键数字（这决定了 Agent 怎么用它）： - 生理滞后：组织间液葡萄糖相对血液葡萄糖滞后 5–15 分钟。血糖在快速变化（进餐后、运动后、胰岛素作用期）时，这个滞后会让 CGM 和实际血糖差得很远。 - 精度指标用 MARD（Mean Absolute Relative Difference，平均绝对相对差异）。新一代产品 MARD 约 7–9%（Dexcom G7、Libre 3 级别），微创 CGM 是 Gold Standard；任何号称无创光学血糖的产品都要拿它做对比。 - 寿命：7–15 天（Dexcom G7 10 天，Libre 3 14 天），到后期酶衰减 + 异物反应包裹 → 精度下滑。 - factory calibration：现代产品出厂标定，无需指血校准。

「无创血糖」为什么这么难（对你判断技术新闻很有用）

葡萄糖在血液中浓度约 5 mmol/L（~90mg/dL），而红外光谱区葡萄糖的摩尔吸光系数极小，且与水、血红蛋白、蛋白、温度的重叠吸收混淆。结果就是：葡萄糖对光谱的贡献可能只占总信号变化的万分之几。要在噪声里提取出这么小的信号，还要排除个体间巨大的皮肤/血流差异——这是物理学级别的困难，不是算法能短期突破的。

判断准则：看到「无创血糖手表」的新闻，先问三个问题：①有没有拿介入式 CGM 或静脉血做同步对照？②MARD 是多少？③是否报告了个体校准需求？如果只用「趋势一致率」「方向一致率」这种指标（例如某些被试 A1C 或静脉空腹血糖的「变化方向一致率」），那基本等于没验证。

目前市面上合法的所谓「手表血糖」，几乎都是多模态建模的趋势/倾向指数（HRV、皮温、睡眠结构、活动等推算），而不是血糖测量。这在监管上属于健康建议而非血糖监测，界线必须清楚。

1.5 惯性与其他

IMU（三轴加速度计 ± 陀螺仪 ± 磁力计） 是除 PPG 外性价比最高的传感器，因为它便宜、极低功耗、而且几乎永不失效。它能做：

  • 步数（峰值检测 + 时频处理，需抗「抖手伪造」）
  • 活动识别（走路/跑步/骑车/游泳/器械/睡眠）：这是经典的 HAR（Human Activity Recognition）问题，深度模型在公开数据集上早已 >95%，难点在个体差异与未见过活动而非训练集精度。
  • 睡眠/觉醒区分（体动 Wear/Donning）
  • 能量消耗（加速度积分 + 心率回归）
  • 跌倒检测（自由落体→撞击→静止三阶段模板）
  • 震颤量化（帕金森病药物疗效评估，已在临床研究中成熟）
  • 呼吸扰动（这是苹果睡眠呼吸暂停检测的核心输入，见 §2.7）
  • 吞咽次数 / 咬合 / 手势 / 打字（扩展交互）

气压计：能算爬楼层（每层约 10–12 hPa 变化被人误解，实际每层 ≈ 0.36 hPa，约 3 米），也能估算海拔适应；配合天气 API 可估算环境气压对生理的影响。

GNSS（双频 L1+L5）：跑步经济性、配速、距离；多星系统（GPS/北斗/伽利略/格洛纳斯）提升城市峡谷精度。它消耗的功耗最高，是穿戴功耗预算的主要矛盾之一。

麦克风：鼾声录音 + 频谱分析可以辅助打鼾/呼吸暂停判断；咳嗽频次是慢阻肺、哮喘、心衰的重要标记；语音的情感韵律（prosody）与认知退化筛查（语速、停顿、词汇多样性）正在成为研究热点。注意：这是隐私敏感度最高的传感器，很多产品干脆不采样只做本地特征。

2.1 链路一：PPG → 心率（HR）

物理

每次心脏收缩把血泵入外周血管，手腕/手指的毛细血管床体积发生脉动性充盈；对绿光而言，血液比其他组织吸收得多得多，于是反射光强出现周期性波动。

PPG 信号可分解为两部分：

I(t) = I_DC + I_AC
I_DC：缓慢漂移（组织、静脉血、呼吸、体温调节）——占绝大部分
I_AC：心动周期导致的脉动——通常只占总光强的 0.1%~2%

注意这个比例：有用的交流成分只占总光强的千分之几。这就是为什么 PPG 处理的第一步永远是 DC 追踪 + AC 放大，AFE 芯片里的环境光抵消和直流扣除电路就是在干这件事。

波形解剖（必须懂，因为后面血压、血管老化全靠它）

一个典型脉搏波包含三段结构：

  • 主波（Systolic peak）：左心室射血产生的压力波峰
  • 重搏切迹（Dicrotic notch）：主动脉瓣关闭叠加外周反射波回传形成的凹陷
  • 舒张波（Diastolic peak）：反射波形成的第二个峰

从波形可提取的形态学特征主要有：收缩期上升时间、最大上升斜率（与心肌收缩力、血管顺应性相关）、主波峰面积、切迹相对位置、波形面积比 K = A_{sys}/A_{total}、增强指数 AIx（Augmentation Index）。这类「脉搏波分析（PWA, Pulse Wave Analysis）」特征，是几乎所有高级心血管估算的共同物理基础。

处理链路

原始 PPG（采样率通常 25~100Hz 或更高）
  → 带通滤波（典型 0.5–4Hz，对应 30–240 bpm）
  → 运动伪影抑制（以 IMU 为参考的自适应滤波 / PCA / SVD / EMD / VMD / 深度学习重建）
  → 心搏检测（峰值法 / 自相关 / 稀疏信号复原 / U-Net 分割）
  → 逐拍 IBI（inter-beat interval）/ PRV 序列
  → 生理合理性检查（相邻 IBI 差 >20% 需判定为异常或伪影）
  → 心率 = 60 / mean(IBI)

精度与失效模式

场景 典型表现
静息 / 睡眠 误差通常 <3 bpm，可接近 ECG 参考水平
稳态有氧跑 光学腕式通常 2%~5% 误差；第三方对比测试中，Apple Watch 对胸带的误差约 0.63%~0.98%，入耳式 AirPods Pro 3 约 1.67%
HIIT / 间歇跑 峰值延迟 2~4 秒，误差显著放大（生理延迟叠加算法平滑）
力量训练 最差：握持、肌肉收缩、手表位移导致严重伪影
冷水 / 低温 外周血管收缩 → 灌注下降 → AC 幅度骤降，甚至测不出
深肤色 / 手腕纹身 黑色素吸收绿光降低 SNR。厂商通过动态调整 LED 输出功率与接收灵敏度部分补偿，但无法彻底消除
节律锁定（cadence lock） 跑步步频恰好与心率频段重叠（160 spm = 2.67Hz，160 bpm = 2.67Hz），频域滤波无法分离

对 Agent 的启示

心率是一个「准但有延迟」的量，不是一个实时真值。 用它做闭环控制（例如「根据实时心率调整今日训练量」）时，必须设计滞后容忍与趋势优先：用 30~60 秒滑动窗口，不要对单点心率做反应式决策。

2.2 链路二：RR 间期序列 → HRV（心率变异性）

物理

心跳不是节拍器。相邻 RR 间期的微小波动来自窦房结对自主神经输入的响应：

  • 副交感（迷走神经）作用快，产生心率的呼吸性变异（RSA，0.15~0.4 Hz 高频带）
  • 交感作用慢（低频带 0.04~0.15 Hz，与压力反射回路相关）

所以 HRV 是自主神经系统功能的一个非侵入窗口——注意是「窗口」不是「测量」：它测不出交感或副交感的绝对强度。

三类特征

时域（最常用、最稳）

指标 定义 含义
RMSSD 相邻 RR 差值平方和均值的平方根 最常用。反映逐拍差异，主要由副交感/迷走张力决定。夜间或晨起 RMSSD 是恢复判断的主力指标
SDNN RR 序列标准差 总变异量。需注意：短时段（<5 分钟）的 SDNN 生理意义有限，常被误用
pNN50 相邻 RR 差 >50ms 的占比 与 RMSSD 高度相关

频域（先把 RR 序列重采样为等间距序列，再用 Welch 或 AR 模型估计功率谱）

频段 范围 解释（存在争议，勿过度解读）
VLF 0.003–0.04 Hz 体温调节、肾素系统；生理意义争议大
LF 0.04–0.15 Hz 传统解读为「交感」，但现代观点认为它包含压力反射的混合成分
HF 0.15–0.4 Hz 呼吸性变异（RSA），主要反映副交感活动
LF/HF 比值 历史上被当作「交感/副交感平衡」，今天被大量方法学者批评为过度简化

非线性：SD1/SD2（Poincaré 散点图）、样本熵、DFA-α1（去趋势波动分析的短期标度指数）。其中 DFA-α1 在运动生理领域被用于划定有氧阈/第一乳酸阈，是目前实用性较强的非线性指标。

四个关键陷阱（做产品必读）

  1. HRV 的个体差异极大（RMSSD 从 15ms 到 150ms 都有正常人），人群分位数对比几乎没有意义，必须做个体内基线。这是 Oura、Whoop、Garmin 全部采用「相对你的基线」呈现的根本原因。
  2. 测量窗口必须标准化：HRV 受呼吸频率、体位、测量时间、是否进食排尿影响极大。只有「晨起、静卧、固定时间、固定姿势」的 RMSSD 才可纵向比较。
  3. PPG-HRV vs ECG-HRV：静息高质量信号下二者在 RR 序列层面高度一致（这是它的合法性基础）；但在运动伪影下，PPG 的 RR 序列会被后处理平滑化，人为压低 RMSSD。所以不要在运动期间用 PPG-HRV 当训练强度指标。
  4. HRV 不是压力，也不是恢复本身。 它同时被睡眠、训练负荷、酒精、感染、脱水、情绪、咖啡因、昼夜相位影响。单看 HRV 下降做归因，是消费级产品最大的解释失效点。

对 Agent 的启示

HRV 的正确用法是「多个原因共同指向的果」，而不是「推断原因的因」。 换句话说：不是「HRV 低了所以今天疲劳」，而是「若 HRV 低 + 静息心率↑ + 睡眠时长↓ + 主观疲劳高 → 大概率确实过度」。多证据汇聚（evidence accumulation）远比单一指标阈值可靠，这是第五章要反复展开的核心方法。

2.3 链路三：双波长 PPG → 血氧饱和度 SpO₂

物理：Beer-Lambert 定律 + 血红蛋白的光学指纹

核心事实：氧合血红蛋白（HbO₂）与脱氧血红蛋白（Hb）在红光与红外光上的吸收系数差异，是这件事的全部基础。

  • 红光（~660nm）：Hb 吸收远大于 HbO₂（缺氧的血液「更暗」）
  • 红外（~940nm）：HbO₂ 吸收略大于 Hb
  • 等吸收点（~805nm）：两者吸收相同，可单独测量血流体积而不含饱和度信息

修正的 Beer-Lambert 定律：

A = log(I0 / I) = ε · c · d · DPF + G
ε：摩尔消光系数   c：浓度   d：光程
DPF：微分路径因子（组织散射导致路径变长）
G：散射损耗项

工程推导的关键是取比值以消去未知的光程 d 与散射项 G：

R = (AC/DC)_Red  ÷  (AC/DC)_IR
SpO₂ = f(R)      ← 经验标定曲线

最后那条 f(R) 必须由厂商用健康志愿者在低氧舱（受控去饱和研究）中标定。伦理上不可能把人降到危险血氧值，因此低于约 80% 的血氧区往往是外推的——这是低血氧区精度差的根源之一。早期常用线性近似 SpO_2 \approx 110 - 25R，实际关系是非线性的。

失效模式

问题 机制
运动伪影 上一节全部适用，低灌注下更严重
低灌注 / 休克 / 低温 AC 幅度降到噪声底，直接失效
肤色偏差 有确凿临床证据的问题：深色皮肤人群的血氧测量存在隐匿性低氧漏检风险（FDA 曾就此发布安全通告）。腕式方案 SNR 本就更低，风险更高
指甲油 / 假指甲 特定色素（尤其蓝、黑）干扰光谱
SpO₂ 是比例而非总量 贫血者 SpO₂ 可为 98% 却严重缺氧（血红蛋白总量不足）；一氧化碳中毒时甚至显示 100%（碳氧血红蛋白被误判为氧合血红蛋白）
测量部位差异 腕式精度显著低于指夹式

对 Agent 的启示

SpO₂ 单次读数的医疗价值很低，但「夜间反复出现的氧减事件模式」价值很高——这正是睡眠呼吸暂停筛查（§2.7）能成立的原因。

请把这条变成你的默认方法：单点有偏 → 重复模式可信。 这是穿戴数据分析里最通用的一条技巧，值得反复使用。

2.4 链路四：IMU → 步数 / 活动识别 / 能量消耗

步数

三轴加速度 → 幅值 |a| = sqrt(ax² + ay² + az²)
  → 去除重力分量（高通滤波 / 姿态解算）
  → 带通滤波（典型 0.5–5Hz，对应 30–300 步/分）
  → 峰值/过零检测 + 自适应阈值
  → 时间窗口去抖（需连续节律才算真的在走）

误计来源：抖手臂、打字、开车、推购物车。成熟方案会结合 GNSS、PPG 与活动上下文做后处理。

更有价值的方向不是「步数」而是步态特征：步速、步幅变异度、对称性、支撑期/摆动期比、转身速度。这些是老年跌倒风险、帕金森病、认知衰退的客观标记——步速在老年医学中被称作「第六生命体征」，对长期健康 Coach 是极高价值的慢变量。

活动识别（HAR）

经典 pipeline（仍有生命力，因为可解释、能耗低）：

滑动窗口（1–5 秒，50% 重叠）
  → 手工特征：均值/方差/能量/熵/FFT 主频/轴间相关系数/姿态角
  → Random Forest / SVM / XGBoost

现代 pipeline：

原始 IMU（或多模态）→ CNN / CNN-LSTM / Transformer → 多分类

清醒认识：公开数据集（UCI HAR、WISDM、Opportunity）上 >95% 精度早已不是瓶颈。真正难的是：

  • 开放集问题：用户做了模型没见过的运动（椭圆机、滑板、举重），模型会自信地误分类
  • 个体差异：老年人、病理性步态与训练集分布差异大
  • 传感器位置迁移：手 vs 腕 vs 口袋 vs 耳朵，同一模型换位置就崩（domain shift）
  • 行为粒度：用户说「我今天动了」，但你要区分是久坐 8 小时里的碎片活动，还是连续 45 分钟中等强度——这才是健康意义上的差别

能量消耗（卡路里）

最诚实的说法：这是估算链条最长、误差最大的指标之一：

EE = f(体重, 年龄, 性别, 心率, 加速度, 运动类型, 环境条件)

业界主流是「心率-耗氧量线性关系」（个体标定后可好很多）叠加「加速度计数回归」。第三方验证中，腕戴消费设备的能耗误差常在 20%~50% 量级。

对 Agent 的启示

永远不要用「今日消耗 2100 千卡」这种精度幻象来做饮食建议。 更好的做法是：

  • 用相对变化（相对你过去 4 周均值），而非绝对值
  • 用强度分层（sedentary / light / moderate / vigorous 分钟数，这套分类源自流行病学大型队列证据），而非卡路里
  • 用体重趋势（7 日移动平均）作为能量平衡的最终仲裁者

这样你依然能自信地谈论运动，但不再依赖不可靠的能量数字。

2.5 链路五：IMU + PPG → 睡眠分期

为什么这是「多模态融合」最好的教科书案例

睡眠分期的金标准是 PSG（多导睡眠监测）：EEG + EOG + EMG + ECG + 呼吸气流 + 胸腹运动 + 血氧，同时记录大脑状态与身体状态。

穿戴设备只有身体侧：IMU（体动）+ PPG（心率/HRV/脉搏波振幅），对应自主神经维度；大脑侧完全没有。

所以穿戴睡眠分期的本质是：用自主神经变化 + 体动，去反演大脑皮层的睡眠分期。 这是一个典型的病态反问题——不同睡眠阶段可以有相似的自主神经表现（例如 N1 与 Wake 的辨别，几乎只能靠体动量）。

生理知识（这是算法的先验，也是特征设计的依据）

分期 自主神经特征 EEG 特征（穿戴看不到）
Wake HR 较高、HRV 较低、体动多 α/β 波，低幅混合频率
N1 入睡期 HR 开始下降，缓慢眼动 θ 波为主
N2 浅睡 HR 进一步降，HRV 上升 θ 波 + 睡眠纺锤波 / K 复合波
N3 深睡/慢波 HR 最低、HRV 最高（副交感绝对主导）、体动最少、呼吸最规整 δ 波（0.5–2Hz）高幅慢波
REM HR 和血压回到接近觉醒水平且变异大，呼吸不规则，肌肉张力消失（所以体动反而可能很少） 低幅混合频率（类似 Wake），伴快速眼动

读懂 N3 与 REM 的差别，你就明白为什么 REM/N3 的混淆远多于 N3/Wake 的混淆。

三代方法

第一代：纯体动计（actigraphy） - 原理：连续静止的一段时间判定为睡眠（Cole-Kripke 类加权移动平均规则） - 性能：检测「睡眠」的灵敏度很高（90%+），但区分「躺床清醒」的特异性很低——躺着刷手机会被判为睡眠 - 今天仍是所有低价手环的实现方式

第二代：HR/HRV + Actigraphy 的传统机器学习 - 每 30 秒一个 epoch，提取时域（RMSSD/SDNN/pNN50）、频域（LF/HF/总功率）、非线性特征，加体动计数，喂给 Random Forest / LSTM - 代表性结果：面向睡眠障碍人群，4 类分期（Wake / N1+N2 / N3 / REM），132 个 HRV 特征 + 活动计数的 LSTM 模型：Cohen's κ ≈ 0.60，准确率 75.9% - 工程痛点：132 个 HRV 特征在嵌入式设备上算不起

第三代：端到端深度学习 + 迁移学习 - 直接输入原始加速度 + RR 间期/瞬时心率序列，让网络自己学表示（Temporal CNN / U-Net / Transformer） - 代表性结果：4 类分期 κ ≈ 0.638、准确率 77.8%，且推理速度快约 50 倍，使嵌入式实时部署成为可能 - 迁移学习是关键：在大规模队列（如 SHHS）预训练 → 在小规模设备专用数据上微调，准确率从 68.9% 提升到 73.8%，κ 从 0.51 提升到 0.59 - Oura 官方表述：其机器学习睡眠分期算法以 PSG 为参照进行了科学验证

κ ≈ 0.6~0.65 算什么水平？ - 人类睡眠技师之间的一致性 κ 约 0.7~0.8 - 所以穿戴处于「接近但未达到人类专家」的水平 - 但这是逐 30 秒 epoch 与 PSG 对比的结果。用户真正关心的聚合量（总睡眠时长、睡眠效率、深睡占比、夜间觉醒次数）误差远小于单 epoch 分类误差——这又是同一个「聚合换稳健」原则。

对 Agent 的启示

  1. 聚合量远比分期的分钟级细节可靠。 用「总睡眠时长」「睡眠效率」「夜间觉醒次数」说话，不要说「你昨晚 REM 少了 8 分钟」。
  2. 睡眠是所有健康行为的枢纽变量。 睡眠不足的下游效应：胰岛素敏感性下降、食欲激素紊乱（ghrelin↑/leptin↓）、运动表现下降、情绪调节能力下降、免疫下降。如果只能给一条建议，通常是睡眠。 这会让你的 Coach 显得比一上来就推 HIIT 的 App 专业得多。
  3. 主观睡眠与客观测量会系统性不一致，而两者都有价值。 客观数据反映睡眠的「量」，主观体验反映睡眠的「质」。失眠的诊断依赖主观体验而非 PSG。

2.6 链路六：PPG / IMU → 呼吸率

呼吸调制 PPG 的三条机制

调制类型 机制 体现在何处
强度变异（RIAV） 胸内压变化 → 静脉回流变化 → 每搏输出量变化 → 脉搏波幅度的呼吸性起伏 波峰高度 / 积分面积
基线漂移（BW） 同一机制，表现为 PPG 的 DC 基线随呼吸慢波摆动 信号基线
频率变异（RSA） 呼吸直接调制心率 → RR 间期的呼吸性起伏 相邻 RR 长度

三条提取路径再融合： 1. 对 PPG 的幅度/积分面积序列做带通滤波（典型 0.1–0.7 Hz，对应 6–42 次/分） 2. 对 RR 间期序列做频域分析，取 HF 峰（0.15–0.4 Hz）位置作为呼吸频率 3. 用机器学习直接回归：输入多通道 PPG + IMU，输出呼吸率

局限：呼吸停止（呼吸暂停）期间调制消失，所以这条链路本身无法察觉呼吸暂停；此外对某些病理呼吸模式（如 Cheyne-Stokes 呼吸）识别能力弱。

一个必须记住的「反向有效性梯度」

一项三星资助的临床研究（195 名睡眠门诊患者同步 PSG）显示：腕式 Galaxy Watch 的夜间呼吸率相对鼻热敏电阻（参照标准）的 RMSE = 1.13 次/分。但分层后：

  • 正常到中度 OSA 人群：准确率 >90%
  • 重度 OSA 人群：准确率降至 79.45%

也就是说：在最需要准确的病人身上最不准。

这是穿戴健康领域反复出现的「反向有效性梯度」现象，值得作为一条方法论记住：在重症/极端生理状态下性能的衰减，是所有数据驱动健康模型的共同软肋，因为训练数据的分布中心在健康人身上。

2.7 链路七：夜间信号 → 睡眠呼吸暂停（OSA）筛查

这是目前最能体现穿戴产品在受监管预期用途与测量机制上差异的一条链路，也是「两条技术路线之争」的好例子。

Apple 路线 vs Samsung 路线

Apple Watch 睡眠呼吸暂停通知（FDA 510(k) K240929，2024-09） Samsung Galaxy Watch 睡眠呼吸暂停功能（FDA De Novo DEN230041，2024-02）
核心传感器 加速度计（不用血氧） PPG 衍生血氧 + 加速度计
信号本质 呼吸努力引起的腕部微小运动（可理解为一台"体动地震仪"） 夜间反复的血氧去饱和格局
输出 「呼吸扰动（Breathing Disturbances）」二分类：升高 / 未升高 二分：是否需就医；衍生估计 AHI
评估窗口 30 天滚动窗口（30 天内至少佩戴睡眠 10 晚） 10 天内至少 2 个有效夜晚（每晚 ≥4 小时睡眠）
训练集 11,000+ 夜的 PSG/HSAT 同步数据，4,700 名成人 620 人配对 PSG 的关键验证研究

如何读这张表：

  • Apple 走「高特异度、低灵敏度」：响了大概率真有（98.5% 特异度），但漏掉约三分之一的真病人。这是典型的筛查器设计取向，目的是避免假阳性引发大规模不必要就医。
  • Samsung 走「平衡」：灵敏度明显更高，但假阳性也更多，且链路依赖腕式 SpO₂，而腕式血氧本身精度弱于指夹式。
  • 两者参照标准不同（HSAT vs PSG），数字不能直接比优劣。
  • 两者都不是诊断工具，只是「去找医生」的触发器。这一点在产品文案和 Agent 对话里必须诚实表达。

Apple 路线的工程智慧在于那个「30 天窗口」

苹果的做法：从加速度计高频信号中提取与呼吸震荡相关的微运动（本质上是 actigraphy 的高阶版本），深度学习模型输出每夜的呼吸扰动值，再在 30 天窗口内判断是否存在「持续升高」。标签来自同步 PSG/HSAT，采用 4% 氧减阈值的事件定义。

为什么是 30 天？ 因为单夜噪声极大（睡姿、被子、伴侣、翻身、环境），但「连续 30 天里多数夜晚都偏高」是极强的稳健信号。这是第三次看到的「聚合换稳健」套路。

做穿戴 Agent 的人，请把这条当成默认建模策略：

当单帧/单夜信号不可信时，不要试图提高单帧精度，而应该拉长观察窗 + 做时间序列聚合。

2.8 链路八：PPG 心动周期图 → 房颤机会式筛查

这是 PPG 最广为人知的受监管筛查应用之一；其架构值得完整学习，但结论仍受具体设备的预期用途约束。

Apple 的实现（五步）

  1. 采集心动周期图（tachogram）：把一段稳定的 PPG 记录转换成「相邻心搏间隔随时间变化」的图，每 2~4 小时采集一次，机会式（opportunistic）——只在用户足够静止、信号质量达标时才采集。
  2. 分类：专有算法判定该 tachogram 是「规整」还是「不规则」。
  3. 级联加密：一旦判定不规则，立即切换为「尽可能频繁但至少间隔 15 分钟」的加密采集与分析。
  4. 触发规则：48 小时内，连续 6 次 tachogram 中有 5 次被判为不规则（含最初触发那次）→ 推送通知。
  5. 重置规则：若在此之前有 2 次被判为正常，则恢复每 2 小时的基线采样频率。

这套规则本质上就是一枚灵敏度/特异度调节旋钮，在「漏诊」与「过度就医」之间做明确的商业与伦理权衡。

性能（务必区分三个来源）

来源 数字 说明
Apple 官方 IFU 灵敏度 88.6%，特异度 99.3% 针对 ECG 贴片确认的 AFib 时段
Apple Heart Study（>40 万人，斯坦福主导） 收到通知的时间点上有 84% 确实处于房颤；收到通知后做一周 ECG 贴片的人中 34% 检出 AFib 房颤是发作性的，一周不发作很正常

架构价值远大于医学价值：请把这套模式搬进你的 Agent

「低成本连续筛查 + 高成本间歇确认」这种两级确认结构，应该被 AI Coach 直接复用。

每天被动监测（睡眠/静息心率/HRV/体重）
  → 发现发现需要复核的趋势信号
  → 在适用人群、禁忌与停止条件明确时，提供低风险问卷或建议联系专业人员
  → 症状、红旗提示、既往疾病、孕期和设备正式告警优先于任何观察窗口

中间那个「主动任务」台阶，是当前绝大多数消费健康 App 缺失的环节，而它是把被动观察升级为主动测量的关键。主动复核的阈值、测试形式和升级路径都应经过前瞻性验证；通用 Agent 不应自行安排可能不适合用户的体力测试。

2.9 链路九：单导联 ECG → 心律失常分类

PPG 只能告诉你「节律不规则」，不能告诉你是什么；ECG 可以。

实现与陷阱

  • 手指按住表冠与背面电极形成回路 → 记录 30 秒近似 Lead I 的波形
  • 自动分类输出：窦性心律 / 房颤 / 心率过高或过低 / 结果不确定（Inconclusive）；后续版本追加「房颤伴高心率」「记录质量差」
  • 实际使用中最常见的失败：心率 <50 bpm、>120 bpm，或处于 100–120 bpm 区间时无法分类 → 输出「不确定」。某些研究中「不确定」可达三分之一的记录。Agent 的对话设计必须能优雅地处理「不确定」，而不是把它显示为一个失败。

一组极具启发性的对比数字

在第三方研究中，同一批记录：

判读者 灵敏度 特异度
医生审阅导出的 PDF 波形 96% 100%
手表内置自动算法 41% 100%

差距来自哪里？自动算法把大量记录标成了「不确定」（它把 31% 的正常节律也判为不确定）。Apple 自己的临床数据（588 例）则显示算法 >98% 灵敏度 / 99% 特异度——实验条件差异很大。

这一课很重要：同一份数据，在「人读」和「算法读」下的可用性差距巨大。所以把波形导出给专业人士的功能，价值往往高于 App 内的自动结论。你的 Agent 应该有一条「我把这份原始记录整理好，你拿去给医生看」的路径。

为什么房颤值得单独强调

  • 房颤 → 左心耳血栓 → 心源性卒中，风险增加约 5 倍
  • 常无症状（阵发性），年度体检一次心电图基本抓不到
  • 高度可干预：一旦确诊可抗凝治疗，大幅降低卒中风险

房颤、高血压、睡眠呼吸暂停，是目前仅有的几个被监管机构认可为「筛查具有临床净收益」的穿戴场景。

AI Coach 应该知道这三项是被监管背书的高价值场景，把用户注意力引导到这里，而不是整天纠结 HRV 的 2 毫秒波动。

2.10 链路十：PPG 波形 → 血压（最重要、也最被误解的一条）

物理：脉搏波传播速度（PWV）的压力依赖性

Moens-Korteweg 方程：

PWV = sqrt( E · h / (2 · ρ · r) )

E：动脉壁弹性模量    h：管壁厚度
ρ：血液密度          r：血管半径

关键生理事实：血压升高 → 动脉壁被撑得更硬 → E 增大 → PWV 增大，脉搏波传播更快。这就是用传播时间反推血压的物理基础。粗略关系（Hughes 方程流派）：

BP = α · ln(PTT) + β

三条代理链路（务必分清）

代理量 定义 可获得性
PTT（脉搏传导时间） 脉搏波在两个动脉位点之间的传导时间（如颈动脉→桡动脉） 需两个传感位点，穿戴上难实现
PAT（脉搏到达时间） 从 ECG 的 R 波峰（心室电激动）到外周 PPG 某个特征点（波足/峰值/二阶导最大点）的延迟 需 ECG+PPG 同步；手表可算，但 ECG 只能按需触发
PWA（脉搏波分析） 只用单个 PPG 波形形态回归血压：上升斜率、K 值、切迹位置、二阶导 / 增强指数、波形面积比等 只需一个 PPG → 最易部署，但最依赖 ML 与个体校准

关键区别：PTT/PAT 是物理机制驱动（有明确力学方程），PWA 是数据驱动（把形态映射到血压）。 且注意 PAT = PEP + PTT——PAT 里包含了射血前期 PEP，而 PEP 受心肌收缩力、情绪、药物影响很大，所以 PAT 比 PTT 更脏。

为什么「无袖带血压」至今没真正成功

这不是算法不够好，而是物理 + 生理 + 校准三重困难叠加：

① 个体校准的必然性与漂移

\alpha, \beta（或神经网络映射）里隐含着个体参数：血管半径、壁厚、路径长度、血液密度。这些都因人而异，而且随时间变化（老化、动脉硬化、妊娠、水合状态、昼夜节律）。后果是：

  • 必须用袖带做初始标定
  • 标定会漂移。Avolio 等人指出：单点标定只确定了曲线上的一个点，斜率可以任意选取，误差会随血压偏离标定点而放大
  • 而「每次测量前先标定」会彻底取消无袖带的意义——这就是著名的无袖带血压悖论

② 校准悖论 / 先验泄漏（Priors Leakage）

研究者发现：某些无袖带系统在仿真评估中，当模型输入包含「标定血压、人群均值、年龄、性别」等先验时，表现比只用生理信号更好。这暗示某些产品可能主要在「记忆」用户上次的标定值与人口统计先验，而非真正测量。

这是一个非常值得 AI 从业警惕的现象——它在穿戴领域的形式是「看起来很准，其实在用先验」，在 LLM 领域的形式是「看起来很懂，其实在背语料」。我们在 §5.4 会再谈这类「伪装成测量的记忆」。

③ PAT 里的 PEP 污染

任何改变心肌收缩力的因素（情绪、REM 睡眠、运动后恢复、升压药）都会改变 PEP → PAT 改变 → 但血压可能没变。这就是为什么运动、睡眠、体位变化时误差最大，而这些恰恰是最需要连续监测的场景。

④ 继承 PPG 的全部失效模式（§2.1）

权威界的态度（2025–2026）

  • 2025 AHA/ACC 高血压指南：明确不建议使用无袖带设备进行高血压的诊断或管理
  • 2025 国际立场声明与 AHA 科学声明：目前没有任何无袖带技术达到临床可用精度
  • 但监管路径在前进：2025 年 7 月，一款无袖带腕式血压系统获得 FDA 510(k) 许可用于居家非处方场景，其获准的适用范围明确要求每 24 小时校准一次以维持精度

Apple HTNF：一个「诚实误用」的绝佳案例

高血压通知功能（Hypertension Notification Feature，FDA 510(k)，2025-09-11 获批）：

这个功能的用途是「给从不体检的人一个去量血压的理由」，而不是「监测我的血压」。

另一条真正走通的路线：表带内置气囊（示波法）

  • Omron HeartGuide（2019 年）：首款手表形态的袖带式示波法血压计，表带内置可充气薄气囊
  • 华为 WATCH D2：微型气泵 + 气囊，已过 NMPA 认证，可被编程执行 24 小时动态血压监测（ABPM）
  • 优点：误差接近上臂式（±3mmHg 量级），因为它真的在测量，而不是估算
  • 缺点：体积、佩戴舒适度；且日间测量时必须把手腕抬到心脏水平（否则静水压效应会引入数 mmHg 误差），睡眠时手腕恰好接近心脏水平，反而更准

夜间血压是心血管预后的最强预测因子之一（优于日间与诊室血压），而它恰恰是「袖带测不了（会吵醒）、ABPM 舒适度差、无袖带方法又最不准」的场景。这是一个明确未被满足的需求缺口——如果你的 Agent 能找到合理解法（机会式夜间多信号融合 + 定期锚校准 + 显式置信度输出），值得押注。

对 Agent 的启示

  1. 如果你没有接入 HTNF、WATCH D2 这类受监管数据源，就不要在你的 Coach 里复述血压数值。
  2. 可行且有价值的做法：把用户的家庭电子血压计读数（手输或智能血压计同步）作为金标准锚点，把穿戴数据作为期间的语境插值，并在界面和话术中明确区分二者的证据等级。
  3. 永远不要说「你的血压是 128/82」，而应该说「上一次测量是 128/82；在这之后的 6 天里，夜间心率和脉搏波特征的走势是……」

2.11 链路十一：Bio-Z → 体成分与水合状态

原理已在 §1.3 讲过，这里补充算法侧要点：

  • 它是回归，不是测量：体脂率来自「脂肪% = f(身高, 体重, 阻抗, 年龄, 性别)」的统计模型。群体上有用，个体偏差可达 ±3~5 个百分点
  • 多频优于单频：单频只能得到总体阻抗；多频（5k/50k/200kHz）才能区分细胞内液与细胞外液
  • 八电极（手-脚）明显优于手腕两点：后者对躯干的代表性有限
  • 最容易自欺的行为：饭后、运动后、桑拿后、大量饮水后立即测量都会显著漂移。这就是为什么体脂秤都要求「晨起排空后」测量
  • 真正有价值的不是体脂率的绝对值，而是趋势与相位角（50kHz 下测得的阻抗相角 θ）——相位角与细胞膜完整性、营养状态相关，在临床营养领域是有意义的参数

2.12 链路十二：皮温 → 排卵、发热、疾病预警

一个残酷而重要的测量事实

  • 手表/戒指用 NTC 热敏电阻（负温度系数：温度升高 → 半导体热激发 → 载流子增多 → 电阻下降）
  • 它测的是皮肤温度，不是核心体温。 皮温受环境温度、血流灌注、衣物、佩戴松紧影响巨大，绝对值几乎没有意义（成人皮肤温度可在 30–36°C 之间大幅波动）
  • 因此所有产品都采用相对个人基线的偏移：
ΔT(t) = T_skin(t) − EWMA_baseline(t−τ)

这也解释了为什么戒指在体温上比手表准：贴合紧密、与外界空气交换少，且指根温度更接近核心温度的调节行为。Oura 官方文档明确表示其温度读数只有相对偏差意义、没有绝对意义。

三条有价值的应用

① 月经周期与排卵确认

排卵后黄体酮上升 → 基础体温上升约 0.3~0.5°C 并维持到月经来潮。于是夜间/晨起皮温的双相曲线（低温相 → 高温相）可以：

  • 回溯性确认排卵已发生（注意：是「已发生」，不是「预测」）
  • 结合静息心率同步上升（黄体期升高约 2–5 bpm）可增强判断
  • 局限：本质是回顾性的，对备孕窗口的指导滞后约一天；且仅对有双相周期的人群有效

② 疾病 / 感染早期预警

这是近年最有说服力的应用之一。生理逻辑：病原体入侵 → 免疫应答 → 炎性反应 → 体温调定点上移，同时伴随皮温↑、静息心率↑、HRV↓、呼吸率↑。

多参数联合远比单看体温有效。这正是 Oura 的「Symptom Radar / 疾病预警」、Whoop 的「Health Monitor」等功能的理论基础。

③ 恢复状态

  • 皮温↓ + HRV↑ → 训练适应良好
  • 皮温↑ + HRV↓ + 静息心率↑ → 应激、过度疲劳、热负荷或感染前兆

对 Agent 的启示

皮温是一个绝佳的「Agent 可以诚实使用」案例：绝对值完全不可用，但相对偏移 + 多参数联合就变成了有价值的健康信号。这是「数据即使没有绝对精度，也能产生决策价值」的最佳教学例子，值得在产品与话术中反复强调。

2.13 链路十三：CGM → 血糖动力学

从单点血糖到代谢画像

CGM 的价值不在单次读数，而在曲线形状与派生统计指标：

指标 含义 参考基准
TIR（Time in Range） 处于 3.9–10.0 mmol/L（70–180 mg/dL）的时间占比 糖尿病 CGM 的常用目标之一；须由治疗团队按人群与治疗方案个体化设定
GV（血糖变异性） SD、CV（变异系数）、MAGE（平均血糖波动幅度） 糖尿病 CGM 的常用参考；不应外推为普通人健康阈值
TAR / TBR 高/低于目标范围的时间占比 TBR <4%，越接近 0 越好

HbA1c 是所有这些的长期平均代理，它看不见波动。两个 HbA1c 都是 7.0% 的人，一个可能非常平稳，另一个可能反复高低血糖。CGM 相对 HbA1c 的增量价值，全部在这里。

健康人群（非糖尿病）使用 CGM 的三个硬结论

  1. 个体间餐后血糖反应差异巨大。 同一份食物（甚至标准化白面包），不同人的餐后曲线天差地别——这是 Weizmann 研究所 Segal 组「精准营养」系列研究的核心发现。人群平均 GI 表对特定个体的参考价值有限。
  2. 这直接催生了「用机器学习预测个体餐后血糖曲线」：输入 CGM 历史、膳食记录、肠道菌群、人体测量、活动与睡眠，预测这个人对这份食物的反应。这是做「AI 营养教练」最硬核的算法地基。
  3. 必须显式建模滞后：餐后 CGM 上升滞后血液 5–15 分钟 → 若你做「进食时机提醒 / 运动降糖建议」，必须以预测式提前动作，而不是反应式。这在闭环胰岛素（人工胰腺）领域已经成熟，在生活方式教练领域还很少有人做对。

对 Agent 的启示（这一条非常关键）

如果你能拿到 CGM 数据，你的 Coach 产品力会发生质变——因为它终于有了即时反馈闭环（吃 → 看到结果 → 改），而 HRV、睡眠、体重的反馈周期是天到周的量级。

  • 短期反馈的行为学习效率远高于长期反馈
  • 但也带来风险：过度关注每一次峰值 → 食物焦虑、进食障碍倾向。产品设计必须内置「把注意力从单次数字转向长期趋势」的机制，例如：只展示 TIR 与周趋势，禁止逐餐评判。

2.14 链路十四：EDA + 多模态 → 唤醒度（而非「情绪」）

原理

汗腺是唯一只受交感神经支配、不接受副交感支配的器官，因此它的活动是交感兴奋的纯净窗口。EDA 信号同样分为两层：

  • SCL（皮肤电导水平）：缓慢变化，反映一般性唤醒背景
  • SCR（皮肤电导反应）：瞬态事件（典型上升相 1–5 秒），反映对特定刺激的交感反应

一个必须说清楚的批判

EDA / HR / HRV 能测的是「唤醒度（arousal）」，测不出「情绪种类」。

这是情感计算领域被反复忽视的基本事实。按 Russell 的情绪环模型（Circumplex Model），情绪空间至少是二维的——效价（valence：正/负）× 唤醒（arousal：高/低）——而 EDA 与 HR 只落在唤醒这一个维度上：

                高唤醒
                  │
        愤怒 ●    │    ● 兴奋
    紧张/焦虑 ●   │       ● 喜悦
  ────────────────┼────────────────► 效价（正/负）
      沮丧 ●      │     ● 平静
        倦怠 ●    │   ● 放松
                  │
                低唤醒
              ↑
    EDA / HR / HRV 只能在这个方向上有分辨力

EDA 在图的左右方向上几乎没有分辨能力。 当一个 App 告诉你「检测到你正在焦虑」，它实际测到的是「你的交感唤醒升高了」——而你在做 HIIT、喝了咖啡、赶地铁、被表白、看恐怖片，都会长这样。

诚实的结论：

  • ✅ 可以做：静息/冥想场景下的唤醒度生物反馈训练（HRV biofeedback 对焦虑与失眠的干预是有循证支持的）
  • ✅ 可以做：把主观报告（EMA）与客观唤醒联合，用客观数据佐证回忆
  • ❌ 不该做：宣称「识别出你的 7 种情绪」
  • ❌ 不该做：用单点唤醒数据直接断言「你压力很大」

对 Agent 的启示

把 EDA / 唤醒当作「一个待解释的信号」，永远不要把它当用户情绪本身。 正确姿势：

「刚才这段静息时段，你的交感唤醒偏高（这是客观数据）。你自己当时是什么感觉？」

让模型的输出是开启对话，而不是下结论。这类「把不确定性暴露给用户，以交换上下文」的设计，是 AI Coach 相较传统仪表盘最大的优势，第五章会详细展开。

第三章 引擎篇：所有穿戴算法共享的那套通用方法

看完第二章的 14 条链路，你会发现它们背后反复出现同一批技术手段。这一章把这些共性抽出来——这是可以迁移到你任何一条新链路上的「方法论底座」。

3.1 第一道关口：信号质量评估（SQI）

穿戴数据的第一原则是：垃圾进 → 更糟的出。 所有严肃的穿戴算法栈，第一层都是 SQI（Signal Quality Index），它的作用不是「美化数据」，而是决定要不要丢弃这段数据。

常见的 SQI 判据：

判据 含义
** perfusion / AC 幅度** I_{AC}/I_{DC} 过低 → 灌注不足（低温、缺血、佩戴松）
模板相关性 当前脉搏波与「典型脉搏波模板」的相关系数，低于阈值判为伪影
生理合理性（plausibility） 心率是否在 30–220 bpm；相邻 RR 差是否 >20%
频谱纯度 主频能量占比是否足够高
加速度能量 同步 IMU 的 RMS 是否超过静息阈值
动态时间规整距离 波形序列与参考的距离

工程洞察：一个设计良好的系统会维护一个「数据可用性账本」：今天 24 小时里，PPG 有多少分钟是可信的？其中夜间睡眠时段的可信覆盖率是多少？这个账本身就是一个高价值特征——它直接决定了用户对设备的依从度与数据可靠性，也是 Agent 判断「今天能不能下结论」的输入。

对 Agent 的实际意义：当设备告诉你心率 178 时，你应该先问「这段数据的 SQI 是多少」，而不是直接推送「你在高强度运动」。 这是专业与业余的分水岭。

3.2 第二道关口：运动伪影消除

这是穿戴信号处理里最核心的技术。方法谱系从简单到复杂：

(a) 自适应噪声抵消（ANC / LMS / RLS）——最经典

结构：把 IMU 信号作为噪声参考输入自适应滤波器，从含噪 PPG 中减去它的估计。

参考输入：三轴加速度 ──► 自适应滤波器 W(z) ──► ň(t)
                                              ↓
含噪 PPG x(t) = s(t) + n(t)  ──►  (+)  ──► e(t) ≈ s(t)
                                  ↑(-)
学习规则：最小化 E[e²(t)]（LMS）或加权最小二乘（RLS）

为什么有效：因为运动造成的伪影与 IMU 测到的振动高度相关，而与真实心动节律不相关。这个方法的功耗极低、可在 MCU 上跑，是绝大多数产品的主力。它也正是 AirPods Pro 3 用来处理跑步落地冲击的技术路径（虽然 Apple 用的是自己的实现）。

(b) 盲源分离（PCA / ICA / SVD）

假设 PPG 多通道观测是若干独立源的线性混合，通过分解把「心动成分」与「运动成分」分离。典型是保留第一个主成分（通常对应最强的周期性——心动）或用 ICA 直接分离。

(c) 时频分解（EMD / VMD / 小波）

把信号分解成若干本征模态，识别落在运动频带（通常 0.5–4Hz 外的特定能量块）或与非生理频带对应的模态，剔掉后重建。注意这会带来相位失真，在需要精确逐拍 IBI/PRV 的场景要谨慎。

(d) 深度学习重建

用 U-Net / Transformer 直接从含噪 PPG 重建干净 PPG，或用 GAN 做同一个任务。优点是效果好，缺点是：①需大量「含噪-干净」配对数据（真实世界的干净标签从哪来？通常只能用 ECG 同步提供 RR 真值，波形真值几乎不存在）；②难以在 MCU 上部署。

(e) 「干脆不算」——机会式采样

这是 Apple 的 IRNF 用的策略，也是最务实的一种：只在信号足够好时才采集和分析。 它的代价是「不连续监测」，但换来的是高得多的稳健性。

给你的建议组合：ANC 做在线实时处理（便宜、必然能做），SQI 做门禁（决定用不用），深度学习只用在「可以离线跑、且错误的代价不高」的环节。不要指望一个端到端神经网络解决所有问题——这是穿戴产品里最贵的教训。

3.3 传感器融合的三个层次

多模态融合有三种基本范式，它们的差别不是技术风格，而是信息损失与对齐难度的权衡：

范式 做法 优点 缺点 典型用处
数据级融合（早期） 把不同模态的原始波形拼成一个张量输入网络 信息损失最小 模态采样率不一致、需严格时间对齐；噪声模态会拖累整体 端到端睡眠分期
特征级融合（中期） 各模态独立提特征，再拼接后联合学习 平衡；可处理不同采样率 手工设计仍有信息损失 主流选择（活动识别、压力检测）
决策级融合（晚期） 每个模态独立出一个结论/概率，再加权投票或用贝叶斯规则合并 最简单、最鲁棒、易调试 丢失模态间的交互信息 Orél产业的发展生成式、健康评分体系

实践中的几个真问题

  1. 时间对齐是所有融合的第一杀手。PPG 25Hz、加速度 50Hz、ECG 512Hz、体温每 5 分钟一次、CGM 每 5 分钟一次——必须通过时间戳重采样统一到公共网格，而插值本身会引入人工相关性。
  2. 缺失模态：用户今天没戴表睡觉；某个传感器接触不好；CGM 第 12 天信号衰减。你的模型必须能在任意模态缺失下工作——这是穿戴领域比 CV/NLP 更难的地方。常见解法是 modality dropout 训练 + 显式的缺失指示向量。
  3. 模态间因果混淆：温度和心率都随昼夜节律变化，如果你直接把它们当独立特征，模型会学到「规律 Shared driver」的假相关。正确处理往往需要先去趋势（detrend）或对每个人做昼夜节律对齐。

3.4 个人基线：穿戴健康的灵魂

这是穿戴健康与「普通 ML」最大的概念差异，也是你最需要内化的一条。

同一个 RMSSD=42ms，对一个基线 65ms 的人是「显著下降」，对一个基线 20ms 的人是「正常波动」。因此几乎所有有价值的穿戴指标都必须是：

指标的意义 = 当前值 相对于 该用户自己的长期基线 的偏移（z-score / 百分位）

3.5 时间尺度工程：不同生理过程有不同的「响应时间」

这是被绝大多数 AI 工程师忽略、但在生理数据里极其关键的一点——所有生理变量都有自己的固有时间常数 τ。用错了尺度，模型就是在找噪声。

时间常数 过程 对 Agent 的含义
秒级 心率对运动的响应（τ≈10–30s）、RSA 实时反馈需容忍延迟；不要做秒级决策
分钟级 HRV 的 RSA、运动后心率恢复（HRR）、餐后血糖开始上升 主动任务的最小合理观察窗
小时级 餐后胰岛素反应、训练后 EPOC、咖啡因 「今天练完之后恢复得如何」的合理尺度

由此衍生出两个必须在产品里实现的概念：

  1. 急性-慢性负荷比（ACWR, Acute:Chronic Workload Ratio）： ACWR = 最近 7 天训练负荷 / 过去 28 天平均周负荷 甜蜜区通常被认为在 0.8 ~ 1.3；>1.5 显著升高受伤风险 这是运动医学里最有用、也最常被误用的一个数字（近年也受到方法学批评，不宜当教条），但它「把急性刺激与慢性适应做对比」的思想是完全正确的。

  2. 昼夜节律相位（circadian phase）：几乎所有生理变量都有 24 小时节律（皮质醇、核心体温、褪黑素、血压、心率、胰岛素敏感性）。同一个指标在一天不同时间测量有不同的意义。 若不建模这个节律，你的模型会把它当成噪声或信号混淆。近年兴起的「昼夜健康 / chronomedicine」正是这个方向的延伸。

4.2 三条最重要的「元结论」

元结论一：被动监测 + 长期窗口 > 主动单次测量

Apple 的高血压通知（30 天窗口）、房颤通知（48 小时 5/6 规则）、睡眠呼吸暂停（30 天窗口），三星的 OSA（10 天内 2 夜）——所有通过监管审查的功能，无一例外都采用了「长期窗口 + 聚合决策」的架构。 这是穿戴行业用十年教训换来的共识。

元结论二：越是"无事发生"的健康人，模型越准

结合前述信号质量限制与适用人群，必须正视一个现实：许多验证研究的参与者和使用条件都较为受限，不能把其表现外推到所有人群。

你的 AI Coach 在健康人身上会表现很好，在真正需要帮助的人身上会逐渐失效。

这句话值得刻在产品团队墙上。应对策略见 §5.9。

元结论三：今天真正被「监管 + 临床 + 商业」三方共同验证的场景，只有四个

  1. 房颤筛查（PPG 机会式 + ECG 确认）
  2. 睡眠呼吸暂停筛查（加速度 或 SpO₂ 路线）
  3. 高血压趋势通知（不是血压测量）
  4. 活动与睡眠的行为改善（作为慢性病预防的一线干预）

如果你的 Agent 想做出「有真实净收益」的东西，这四个是起点，不是全部，但它们是目前唯一可以诚实承诺的领域。

第五章 Agent 篇：AI 健康教练算法研发需要拓展的 12 个维度

前面四章是「把数据做出来」。从这一章开始是「把决策做对」——这才是 AI 健康教练 (Health Coach Agent) 真正的研究与工程难点。

我的核心判断是：

做穿戴 Health Coach Agent，难点从来不在模型架构，而在于：你对生理测量的谦卑程度、对时间的理解、对因果的坚持，以及对自己不确定性的诚实。

下面 12 个维度，按「我认为的投入产出比」排序。每个维度我会给三部分：为什么重要 → 具体要学什么 → 怎么落进产品。

D1. 测量科学素养（Metrology）：学会把每个数字当成「估计值」

为什么最重要

我在调研中反复看到同一个模式的失败：工程团队拿到了 heartRate、hrv、sleepScore 这些 API 返回值，然后当作「用户真实的心率」去做决策。殊不知它们分别是：

  • 一个经过多层滤波与平滑、有 2–4 秒延迟的估计
  • 一个强依赖测量窗口标准化的统计量
  • 一个厂商私有权重算出的、定义都无从查证的综合分

不具备测量科学素养的团队，会造出一个「很自信地错」的产品。 而这在一个涉及医疗建议的场景里，代价远大于收益。

要学什么

概念 为什么必须懂
准确度（accuracy）vs 精密度（precision） 穿戴设备往往精密度尚可（重复性好）但准确度差（有偏）。对趋势跟踪来说，精密度比准确度更重要——这是穿戴数据的合法性基础，也是你做设计取舍的依据
Bland-Altman 分析 vs 相关系数 相关系数是穿戴领域最常见的统计骗术：两个测量高度相关，但一个系统性偏高 20%。永远用 Bland-Altman（差值 vs 均值图）和平均绝对误差/ MARD 类指标，而不是 r

  "evidence_note": "绝不作为压力的直接证据；需与至少2个其他指标联合"
}

这一步的收益极大：它让你的 Agent 天然不会说出「你的 HRV 是 38ms，所以你压力很大」这种话，因为它读到的上下文里写着不可这样使用。而且它强制团队把「我们知道什么、不知道什么」显性化。

D2. 生理动力学与时间尺度：学会正确的决策节奏（决策尺度）

为什么重要

大部分 AI Agent 产品的最大缺陷是决策节奏错了：

  • 看到 HRV 一天低就建议休息（实际是噪声）
  • 第 5 天就说「你的训练方案有效」（实际 VO₂max 变化需要 6–8 周）
  • 用户体重一天涨 0.8kg 就发警报（实际是水合波动）

生理系统的时间常数决定了 Agent 的行为节奏。 复习 §3.5 的时间尺度表，然后往下落实三件事：

要学什么

  1. Supercompensation（超量恢复）模型与训练负荷理论 - Fitness（慢性适应）/ Fatigue（急性疲劳）/ Form = Fitness − Fatigue - Banister impulse-response 模型：把训练量当输入、把表现当输出的双阶线性时不变系统 - ACWR（急性:慢性负荷比）：甜蜜区 0.8–1.3，>1.5 风险显著升高（近年有方法学批评，不宜当教条，但思想正确）
  2. 昼夜节律科学（Chronobiology） - 核心体温、皮质醇、褪黑素、血压、胰岛素敏感性都有 24h 节律 - 胰岛素敏感性与食物热效应下午比晚上更好；运动时间（chronotherapy）会影响效果 - 昼夜相位偏移（social jetlag）本身就是一个健康风险因子 - 实践含义：把 time-of-day 作为模型的一个显式特征，而不是噪声
  3. 睡眠稳态模型（Two-Process Model） - Process S（睡眠压力常数上升）+ Process C（昼夜节律）→ 决定睡眠时机和质量 - 这是理解「为什么熬夜后补觉不能彻底恢复」的模型基础
  4. 长期适应vs短期波动的区分：最小有意义变化不等于差异、测量误差 vs 真实变化 → 用最小可检出变化（MDC, Minimal Detectable Change）判断「这个变化是真的吗」

怎么落进产品

做一个「决策日历」（Decision Cadence）配置表，明确写下每一种洞察的合理尺度：

洞察类型 合理时间窗 举例
实时反馈（秒~分钟） 运动中 心率区间提醒、卡路里实时显示
当日总结（24h） 每日早晚 睡眠回顾、当日活动达成、早起为社会
周度趋势（7d） 每周 HRV/RHR 双基线对比、训练负荷平衡、睡眠债务累积
月度评估（28d） 每月 体重趋势线、运动习惯稳固度、周期规律性
季度/半年（3–6月） 长期目标 VO₂max、静息心率、代谢指标的真正变化

并且，把这条明确写进 Agent 的系统提示：

单日数据通常不足以支持归因或效果结论；观察窗口应由具体问题、信号质量和验证证据决定。出现症状、红旗提示、既往疾病相关变化或设备正式告警时，应优先遵循设备说明与医疗升级路径，而不是等待固定天数。

D3. 隐状态推断：从「指标」到「状态」

为什么重要

用户的真实生理状态（恢复程度、应激水平、代谢健康、训练适应）是不可直接观测的隐变量（latent state）。你观测到的是它的若干带噪声的「果」。

这是一个标准的状态空间模型（State Space Model）问题：

状态方程： x_t = A·x_{t-1} + B·u_t + w_t     （隐状态演化 + 训练/饮食/睡眠等输入 + 过程噪声）
观测方程： y_t = H·x_t + v_t                  （多个带噪观测：HRV、RHR、皮温、主观评分…）

卡尔曼滤波（及其非线性扩展 EKF/UKF/粒子滤波）就是这个问题的标准解法。 这是我认为最应该被 AI 工程师引入穿戴领域、但目前极少被使用的一组工具。

它的实际威力在哪

假设我们想推断「用户的真实疲劳水平 x_t」，手上有四个带噪声观测：

观测 y 噪声来源
RMSSD 下降 测量伪影、昨晚餐食、室温
静息心率上升 睡眠不足、脱水、饮酒
深睡比例下降 分期算法误差、睡前饮酒
主观疲劳评分（EMA） 回忆偏差、情绪状态

单独看任何一个都不可靠。但卡尔曼滤波（或任何贝叶斯状态推断）会：

  1. 按每个观测的噪声方差加权融合（今天是夏天，我知道皮温传感器不太行 → 降权）
  2. 按状态演化的惯性平滑（疲劳不会一天暴涨暴跌 → 抑制单点跳变）
  3. 输出带置信区间的估计：\hat{x}_t \pm \sigma_t

第 3 点是关键：你的 Agent 终于可以对用户说「我有 75% 的把握你今天处于过度疲劳」而不是「你今天状态不好」。

怎么落进产品

  • 用任何一款贝叶斯时间序列库起步（Python 的 statsmodels、pykalman、pymc、cmdstanpy）
  • 最小可行版本：一维隐状态 + 3~5 个观测的一阶卡尔曼滤波，几百行代码就能上线
  • 把输出的后验分布作为 LLM prompt 里的上下文：「恢复状态估计 62/100，95%CI [48, 76]，较昨日下降 8 点」
  • 主观报告（EMA）作为观测之一纳入模型——这一点极其重要，且恰恰是统计学上最优雅的做法：主观体验有偏差但也有信息客观数据缺失的那部分

D4. 个性化与 N-of-1：穿戴健康的统计分析单位是「人内」，不是「人间」

为什么重要

这是穿戴数据最反直觉的一点。在传统 ML/NLP 里，我们追求「更多样本 = 更好」。在穿戴健康里：

10,000 个人 × 1 天的数据，价值远小于 100 个人 × 100 天的数据。

因为绝大部分生理变量的个体间方差远大于个体内方差（RMSSD、静息心率、体温、餐后血糖反应都是如此）。用群体模型套个体，得到的很可能是一个「对所有人都平均不错、对任何一个人都不准」的东西。

要学什么

方法 用途
N-of-1 试验设计 单个个体的交叉对照试验（ABAB 设计），是精准健康的统计学基础。已有一批高质量的临床案例（见下文）
混合效应模型（Mixed-effects / HLM） 同时估计群体效应与个体随机截距/斜率。医学 RCT 的标准分析工具
层次贝叶斯模型 群体先验 + 个体数据 → 个体后验。数据少时向群体收缩，数据多时向个体倾斜（partial pooling）。这几乎是穿戴健康的"最优解框架"
EMA（生态瞬时评估） 在自然情境下多次采样主观状态避免回忆偏差。这是把主观与客观对齐的唯一严肃方法
个体间/个体内方差分解（ICC） 先算 ICC（组内相关系数）判断该变量主要是「人各不同」还是「日常波动」，决定建模策略

一个重要的现实例子

2026 年发表在 npj Digital Medicine 上的 PerMA 试验（斯坦福，n=50，单臂开放标签）是一个很好的模板：

  • 用 2 周数字化监测（每日 4 次手机 EMA + 手表客观数据）为每个人单独建立机器学习模型
  • 找出「对这个个体而言最预测其情绪的生活方式因素」（有人是睡眠，有人是社交，有人是运动）
  • 生成个体化的行为增强方案（iMAP），配合每周一次人类教练
  • 结果：PHQ-9 平均下降 3.5 分（Cohen's d = −0.89）， clinician-rated HDRS 下降 7.2（d = −1.03），12 周随访维持
  • 并且：决策算法与 LLM 能够匹配人类教练的 iMAP 分配，准确率最高达 95%

这个试验就是「N-of-1 ML + LLM Coach」的最清晰示范。它告诉我们：与其训练一个"识别所有人压力"的通用模型，不如为每个人训练一个"识别哪件事在影响他"的小模型。

另一个待出的里程碑是斯坦福 My Heart Counts 2.0（2026 年 3 月开始招募，目标 N=15,000，英美两国）：在前瞻性数字队列中嵌入随机交叉试验，比较「基于跨理论模型（TTM / Stages of Change）的 LLM 生成个性化提示」vs「通用提示」，主终点是日均步数。这类研究的结果会在未来 2–3 年内定义「LLM Coach 到底有没有用」这个争论。

怎么落进产品

  1. 冷启动：用层次贝叶斯从群体先验起步，随着用户数据累积逐步个性化
  2. 至少保留 14 天的「只观察、不归因」期，用来建立个人基线
  3. 主动 EMA 设计是你的秘密武器：每天 1–2 个极低负担的问题（如 1–5 分的精力条），价值超过一堆被动传感器
  4. 把「个体 causality discovery」作为产品功能：找到「对你而言，睡眠不足 → 次日 HRV 下降 → 下午精力低」这条属于他的链路

D5. 行为改变科学：LLM Coach 的「内容」从哪来

为什么重要

很多健康 AI 团队的假设是：LLM 已经足够强，只要把生理数据塞给它，它自然能给出好的健康建议。

这是个危险的假设。LLM 知道很多健康知识，但几乎不知道行为怎么改变。 而健康教练的价值 100% 落在后者。

公共卫生界有一个稳定且被反复验证的结论：知识不足很少是行为失败的原因，环境与动机才是。 你知道熬夜不好，但你还是刷到两点——这不是认知问题。

必须学的行为理论框架

框架 核心 产品映射
COM-B 模型 行为 = 能力(Capability) × 机会(Opportunity) × 动机(Motivation)。英国 NICE 与行为改变车轮（Behaviour Change Wheel）的基础 归因框架：用户不运动是因为「不知道怎么练」(能力)、「没时间/没场地」(机会)、还是「不想动」(动机)？三者干预完全不同
跨理论模型 TTM（Stages of Change） 前意向 → 意向 → 准备 → 行动 → 维持 最重要的实用框架：对「前意向期」的人讲训练计划是浪费时间；对他要做的是动机的唤起。斯坦福 MHC 2.0 的 LLM prompting 正是基于它
自我决定理论 SDT 自主性、胜任感、归属感是内在动机的三大支柱 为什么「外部奖励/打卡 streak」长期有害而「自主选择」长期有益；为什么把目标变成"你要完成"会摧毁动机
执行意图 / If-Then Planning 「如果 [情境]，我就 [行为]」的具体计划显著提升执行率 直接可产品化为 Coach 的核心输出形式
习惯形成（Habit Formation） 线索→行为→奖励的自动回路；平均形成时间被高估，中位约 10 周量级且个体差异极大 不要承诺 21 天养成习惯
动机性访谈（Motivational Interviewing） 开放式提问、肯定、反映性倾听、总结；唤起当事人自己的论据 这正是 LLM 的天然强项（对话生成），也是 LLM Coach 最应该被训练的方向
助推 / 选择架构 改变环境而非改变人 冰箱里放什么、App 默认选项、运动鞋放在哪里

LLM Coach 的证据现状（要诚实）

截至 2026 年中的状态：

  • PerMA 试验（n=50）：LLM 匹配人类教练决策准确率最高 95%，个体差异化的 ML iMAP 显示出有临床意义的抑郁改善（单臂，需 RCT 验证）
  • My Heart Counts 2.0（N=15,000，2026 年 3 月启动）：第一个大规模检验 LLM 生成 coaching 提示 vs 通用提示的 RCT，尚无结果
  • 普遍现状：大量「AI Coach」产品没有公开发表的疗效数据

诚实的结论：LLM Coach 目前处于「有希望、有初步试点证据、缺乏大规模确证性 RCT」的阶段。

怎么落进产品

  1. 把行为理论的 Operating Promise：对的不同 TTM 阶段用完全不同的对话策略。 这比任何 prompt 技巧的影响都大。
  2. Prompt 里注入结构化的用户状态，而不是 raw data dump： 用户状态： - 行为改变阶段：准备期（已表达意愿，尚未行动） - 主要障碍类型（COM-B）：机会型（工作日午休只有30分钟且健身房远） - 自主性倾向：高（讨厌被安排） - 已承诺的最小行动：工作日午餐后步行 10 分钟 → 本轮目标：协同设计一个他主导提出的、明天可执行的具体计划；不要给方案清单，要提问。
  3. 训练/评测 LLM Coach 的指标不应该是「回答好不好」，而应该是「是否推进了行为阶段」（从前意向→意向→准备→行动→维持）。这是唯一诚实的代理终点，且可以做成 rubric-based LLM-as-judge 评测集。

D6. 主动测量：你的 Agent 应该能设计「生理测试」，而不只是读数据

为什么重要

回到 §2.8 那个洞察：Apple 的架构是「被动机会式筛查 → 触发加密采集 → 通知 → 就医」。中间那个「加密采集」本质上是一次主动测量。

当前的消费健康 App 几乎全是被动数据消费者。 但真正有诊断价值的很多东西，必须通过主动任务来获取：

主动任务 可获得什么 医学依据
6 分钟步行测试（6MWT） 心肺适能、功能容量的粗略估计 临床标准工具，有明确参照方程
直立/站立测试（Orthostatic test） 自主神经功能、体位性心动过速、脱水 HR 增幅 >30bpm 提示 POTS/脱水/自主病变
深呼吸 HRV 测试（RSA 测试） 副交感功能储备 标准化的临床自主神经检查（Ewing battery）
30 秒坐立测试（30-second Chair Stand） 下肢力量与功能 老年功能评估标准工具
握力测试（外接设备） 肌肉力量，是全因死亡率的强预测因子 大型 cohort 证据（PURE 研究）
结构化心肺运动测试（需设备） VO₂max 金标准 实验室标准
问卷：PHQ-9 / GAD-7 / PSQI / STOP-BANG / IPAQ 抑郁、焦虑、睡眠质量、OSA 风险、活动量 全部有验证的量表

怎么落进产品

设计一个「Assessment Protocol」工具箱，你的 Agent 在系统里应该像医生一样：

被动数据发现异常（例如静息心率连续 5 天上升 8bpm）
  → Agent 主动调用评估工具：「要不要花 1 分钟做一个站立起测试？这个能帮我们判断
     是脱水、疲劳还是别的。」
  → 用户执行（穿戴 + 手机引导计时）
  → 结果入库，成为新的结构化特征
  → 更新推断（贝叶斯更新）

这个设计有三个巨大好处： 1. 数据质量远比被动采集高（标准化条件下） 2. 它本身就是一次干预（用户在参与自己的健康评估，这是 SDT 里自主性的体现） 3. 它是 LLM Agent 最好的工具调用（tool-use）落地形态——比让它调天气 API 有意义得多

D7. 因果推断与 Bandit：把「相关性」升级为「可行动的因果」

为什么重要

你的 Agent 每天在向用户提建议。每一条建议都是一个干预。你的系统是否有能力知道哪条建议真的有效？

绝大多数产品的答案是：不知道。它们用留存、打开率来评价。而这带来一个严重问题：

Engagement（参与度）作为健康产品的北极星指标是有害的。

最能提升 engagement 的东西，往往不是最能改善健康的东西：焦虑驱动的红点通知、夸张的警告、社交比较、连续打卡的损失厌恶。这些手段会同时提升 DAU 和用户的焦虑水平。

要学什么

方法 适用
随机对照试验 RCT 最可靠，但成本高、周期长。适合关键功能一次
微随机试验 MRT（Micro-Randomized Trial） 最适合穿戴 JITAI 的方法：在成百上千个决策点上随机决定是否推送，直接估计「推送 X 的即时因果效应」。这是行为科学界为穿戴干预量身打造的工具
多臂老虎机 / Contextual Bandit 在线学习「在状态 s 下推送干预 a 的效果」，自动平衡探索与利用。这是 LLM Coach 最强、最现实的推荐引擎形态
时序差分/强化学习 用于长期目标分解与序列决策（但要注意样本效率与安全性）
Off-policy evaluation（离线策略评估） 用历史日志估计新策略效果，不必上线。穿戴场景必需的省钱工具
因果图（DAG）/ do-calculus 明确识别混杂变量（confounders）并避免「控制了对撞机」这类经典错误
工具变量 / 孟德尔随机化（Instrumental Variables / Mendelian Randomization） 用遗传变异作工具变量推断因果（如「睡眠是否真的导致抑郁」）

一个必须建立的因果「陷阱清单」

穿戴数据的观察性分析里有几个特别常见的假因果：

  • 反向因果：不是「睡眠差导致焦虑」，可能「焦虑导致睡眠差」。因为两个方向的滞后效应都有，简单的滞后回归会得出错误结论
  • 共同驱动（confounding by indication）：感觉不舒服的人更容易躺平 + 更容易戴表监测 → 得出「戴表导致不活动」
  • 健康用户偏差（Healthy user bias）：依从性好的人本来就更健康，于是任何产品看起来都有效
  • 回归到均值：用户在最差的一天开始用你的产品，第二天自然变好，看起来像效果
  • 测量缺失非随机（MNAR）：用户停止佩戴手表往往发生在状态差的日子（住院、生病、情绪低落）→ 缺失本身就是最强的信号之一，而绝大多数分析直接丢掉它

怎么落进产品

  1. 把每一次干预当成一次随机化机会：至少用 ε-greedy 或 Thompson Sampling 做 contextual bandit，而不是固定规则。这是最低成本、最高收益的一步。
  2. 记录完整的干预日志：做干预决策时的上下文状态 s、可选动作集 A、实际选择 a、随后的 outcome y。没有这个日志你永远无法评估或改进。
  3. 用 off-policy evaluation 定期在离线评估「如果换成新策略会怎样」，再上线。
  4. 把符号移動到指标体系上：不要以 DAU 为主指标；改用三层指标：
层次 指标 说明
参与层（必要但不充分） 周活跃天数、有效交互天数、任务完成率 是前提，不是目标

D8. 数据工程与互操作：脏活决定上限

为什么重要

这一节最不性感，但我认为它是决定 Health Coach 产品成败的第二重要因素（第一是 D1 的测量素养）。

原因很简单：你的 Agent 是在真实用户的数据流上运行的，而这些数据流是：多源、异步、有缺失、单位混乱、时间戳错位、且设备型号带来的语义差异根本无法通过接口消解（同样是 "sleepScore"，Apple 和 Oura 和 Garmin 的定义完全不同）。

必须处理的具体问题

① 互操作标准 - HL7 FHIR（尤其是 Observation、Patient、Condition、CarePlan 资源）是医疗互操作的事实标准，FDA 与 EHR 广泛采用。HealthKit 是健康/健身样本 API；Health Records 可读取由支持机构提供的 FHIR 临床资源，互操作时必须显式定义映射、版本与单位。Apple Health Records 文档 - Apple HealthKit（iOS）/ Google Health Connect（Android）：消费侧的入口。它们的类型体系、单位（HKUnit）、数据来源（HKSource）模型值得完整学习 - Open mHealth：为穿戴数据设计的 schema 集合，比 FHIR 更贴近穿戴场景 - IEEE 1752 / ISO/IEEE 11073：个人健康设备（PHD）通信标准

② 数据缺失的三种机制（这是统计功底的分水岭） - MCAR（完全随机缺失）：无所谓，直接删 - MAR（随机缺失，缺失概率可由已观测变量解释）：多重插补 / IPW 加权 - MNAR（非随机缺失，缺失本身携带信息）：穿戴数据的常态。停用=病了=焦虑了=忘了=度假了。必须显式建模「缺失指示变量」，并且永远把"多久没同步数据"当作一级特征

③ 单位与时间 - UTC vs 本地时区；夏令时切换（每年两次，必有一个 bug） - 旅行跨时区：用户的「夜间」是哪里的时间？ - 单位统一到 SI / UCUM：mmol/L vs mg/dL（血糖换算因子 18）、lbs vs kg

④ 多设备融合 同一用户可能同时有 Apple Watch + Oura Ring + CGM + 智能体重秤。决策优先级不是「哪个更准」，而是「哪个在你今天拥有的数据里最可靠」。这需要维护一个 source-of-truth 仲裁层。

⑤ 数据契约（Data Contract）与漂移 穿戴厂商会静默更新算法；同一指标的历史值可能因为算法变更而不可比（这在业内极常见，且几乎从不明示）。解决办法：记录每条数据的 source_algorithm_version，并在检测到分布漂移时重新校准个人基线。

D9. 不确定性量化、公平性与「失效的优雅」

为什么重要

第四章的元结论二我们已经说过：你的模型在最需要帮助的人身上最容易失效。 加上这一节的另外三条失效，合起来构成「穿戴 AI 的系统性公平性问题」：

失效类型 具体表现 缓解
肤色偏倚 光学 PPG/SpO₂ 在深肤色人 SNR 更低；SpO₂ 隐匿性低氧漏检有 FDA 安全通告 报告按肤色的分层性能；避免过度依赖光学校准
性别偏倚 女性-specific 生理（周期、妊娠、绝经）在训练数据中长期代表性不足 分层评测；周期建模
年龄/体型偏倚 老年人皮肤松弛、灌注差、病理步态；BMI 极高者光学路径不同 分层评测；明确适用人群
疾病状态偏倚（反向有效性梯度） §2.6 已述 在目标人群中而非健康人中验证
种族/社会经济偏倚 训练队列主要是高教育、高收入、白人参与者 主动招募；报告外部效度

要学什么

  • 不确定性量化：Bayesian neural network / Deep ensembles / Conformal Prediction（尤其是保角预测：给出有统计保证的预测区间，且不依赖分布假设，非常适合医疗场景）
  • 选择性预测 / Abstention：模型可以「弃权」。在健康场景里，「我不知道」的处理策略比猜重要一倍
  • 分布外检测（OOD）：用户的生理进入了模型没见过的状态
  • 公平性评测：分层性能指标（subgroup performance）、equalized odds、不能只看整体 AUC
  • ** calibration（校准）：模型输出的概率是否与实际频率一致。一个说「80% 概率XX」但只有 40% 发生的模型，比一个老实说「50%」的模型危险得多。可靠性曲线（reliability diagram）与 Brier score 是必备工具**

怎么落进产品

一个我认为应该成为行业标准的「不确定性三级的界面/话术约定」：

置信度 呈现形态 用户话语示例
高（>90%） 陈述句 「你的数据显示…」
中（60–90%） 带限定词 + 建议验证 「数据提示… 如果你感觉不是这样，我们可以再看看」
低（<60%） 转换为提问 「我注意到一个变化但不确定原因——最近睡眠和之前比怎么样？」

第三行就是前面 §2.14 讲过的「把不确定性转化为对话」。这是 LLM Agent 相比传统仪表盘最大的结构性优势，值得作为核心设计原则。

D10. 合规、监管与安全边界：Red Line 在哪里

为什么重要

健康是少数几个「说错话要付法律责任」的领域。而且监管并不是在阻挡创新，恰恰相反，它清晰地画出了哪些地方值得创新。

必须知道的监管框架

管辖区 关键概念
美国 FDA SaMD（Software as a Medical Device）框架。三类路径：510(k)（实质等同 / Apple 房颤通知、HTNF 走这条）、De Novo（全新类别 / Samsung OSA 走这条）、PMA（最高风险）。还有 De Novo / 510(k) 的变更控制计划（change control plan）——你更新模型也需要监管许可，这就是为什么 Apple 等厂商会「锁定模型」
欧盟 MDR（医疗器械法规）+ CE 标记；Class IIa 以上需公告机构审核
中国 NMPA 二类医疗器械（多数健康手表/血压/ECG 走这条）与三类。近年 CGM、Watch D2 类产品均获批；同时涉及 AI 的功能遵循《人工智能医疗器械注册审查指导原则》
wellness vs medical 边界 关键的红线：是否受医疗器械监管取决于完整的预期用途、功能、证据与风险，不能只按用词二分；应逐法域评估。FDA general-wellness guidance。即使上游设备不报告数值，下游产品仍须按自身预期用途、证据与风险单独评估。
数据隐私 GDPR（欧盟，健康数据是特殊类别数据）、HIPAA（仅适用于 covered entities 及其 business associates）、中国《个人信息保护法》+《数据安全法》+《人类遗传资源管理条例》（涉及生物样本的严格限制）、Apple/Google 平台对健康数据的特殊规则（不允许用于广告、不允许非必要共享）

LLM Coach 特有的四类风险

  1. 幻觉（Hallucination）：编造一个血压值、虚构一条医学引用。缓解：强制「结构约束生成」——LLM 只能引用系统提供的已验证数据，禁止自由生成数字；输出端做规则校验与数据源回溯
  2. 越界诊断：用户说头痛，Agent 说「你这是偏头痛，建议吃 X」。这是明确的执业行为（practice of medicine）。安全做法是：提供可能性 + 说明哪些情况需要立即就医 + 不给出诊断结论与药物建议
  3. 遗漏告警：用户描述了红旗症状（胸痛、卒中征象、自杀意念），但 Agent 继续聊运动计划。必须有独立于 LLM 的「红旗过滤器（red flag triage）」，用规则或小模型旁路，识别后强制切换为就医引导
  4. 过度医疗化 / 医源性焦虑：每天都在告诉用户有什么异常 → 焦虑升高 → 更多异常 → 更多推送。这个正反馈回路是真实存在的损伤路径。 需要在产品层面设置「静默日」「警觉预算（alert budget）」

落地清单

  • [ ] 明确定义产品的 intended use（预期用途）与 claim（声称），写在 PRD 首行
  • [ ] 建立「不能说的词」词表：诊断、治疗、治愈、预防、检测（用于医疗声称）、建议服用…
  • [ ] 设计「红旗三级分流」流水线：红旗规则旁路 → 通用建议 → 个人洞察
  • [ ] 所有 LLM 输出的数字必须从结构化数据源注入 + 输出前校验
  • [ ] 模型版本 + prompt 版本 + 知识库版本全链路记录，支持事后审计与回滚
  • [ ] 隐私设计：本地优先（on-device first）、数据最小化、明确的用户撤回权

D11. 基础模型与表征学习：什么时候用，什么时候别用

现状：穿戴生理信号的 Foundation Model 时代已经开始（2025–2026）

这是过去两年这个领域最显著的变化。几个代表性工作：

模型 机构/来源 预训练数据 关键做法
PulseOx-FM Weizmann Institute（Eran Segal 组，Human Phenotype Project） 10,704 名参与者的 42,282 夜睡眠记录，共 6,995,558 段脉搏血氧片段 自监督学习。用实际年龄作为全局健康基准任务验证表征质量；表征可预测 64 个表型靶标；前瞻性预测正常血压者的 2 年高血压发病；夜间嵌入还能追踪次日血糖/饮食/活动状态
MMR（Masked Multiscale Reconstruction） 厂商级研究团队， NeurIPS 2025 Workshop 约 17M~18M 段 10 秒 PPG，来自 32K~41K 智能手表用户（自然场景） 小波多分辨率分解 + 随机 mask 小波系数再重建。强迫编码器同时学习细粒度波形形态与全局节律动态。在多数健康任务上达到或超过同类开源 PPG 基础模型
Pulse-PPG University of Memphis + UIUC（UbiComp/IMWUT 2025） 100 天自由生活场景研究，120 名参与者的原始未清洗 PPG 在现场数据而非临床数据上预训练；RelCon 相对对比式学习目标 + 可学习 motif 距离。核心结论：现场数据预训练的跨数据集泛化显著优于临床数据预训练
SleepFM 多模态 PSG 睡眠基础模型 完整多导睡眠监测（含 EEG/ECG/EMG） 展示了单次夜间记录能做多广的疾病预测；缺点是需要 PSG，难以规模化
PaPaGei / GPT-PPG 开源社区 不同规模的公开与私有 PPG 数据 提供可复用的开源基线
端侧卷积 FM NeurIPS 2025 Workshop 8 万小时 PPG 0.31M 参数 vs Transformer 的 110M；内存 3.6MB vs 441MB；CPU 4× / GPU 20× 加速；在 10 项临床分类任务上持平或超越。这是对 Agent 最实用的一条路线

三个务实的判断

判断一：基础模型解决的是「单任务数据不足」的问题，而不是「数据充足任务」的问题。 如果你的下游任务有数万标注样本，微调一个专用骨干网络通常仍会优于通用 FM。FM 的价值在于长尾任务——特别是那些「某一类标签极少但是你知道生理上应该存在信号」的任务（例如罕见心律失常、早期代谢功能紊乱）。

判断二：表征好不好，必须用统一的 probe 协议评估，不要用你自己的微调结果自证。 标准做法是：冻结编码器 → 训练线性探针（linear probe）→ 在多个下游任务上比较。如果一个所谓 FM 的线性探针还不如手工特征 + XGBoost，那它的表征就是失败的。这一点在 CV/NLP 已经是常识，在穿戴领域还常常被跳过。

判断三：端侧部署是硬约束，别一开始就搞大 Transformer。 上面那篇 0.31M 参数的工作给出了明确信号：卷积 + 时间局部性的归纳偏置，与非平稳的生理波形天然更匹配，参数量差三个数量级而性能不降。对要在手表上跑的感知层来说，这才是正确路线。

建议的采用路径

1. 先用开源 FM（Pulse-PPG / PaPaGei 等）在你自己的数据上跑线性探针，建立 baseline
2. 同时训练一个「手工特征 + 梯度提升树」的传统 baseline ← 不要跳过，这是最重要的对照
3. 只有当 FM 显著超越 baseline 时，才进入微调阶段
4. 上线时考虑蒸馏到小模型（端侧部署）
5. 关键：评测必须做「人内分层」「时间序列划分（不能用随机打乱）」「跨人群外部验证」

最后一个陷阱：穿戴数据的划分必须是按 subject 划分且按时间划分。随机打乱 train/test 会让同一个人的相邻片段同时出现在 train 和 test 里，导致虚高的性能——这是穿戴 ML 论文里最高频的错误，没有之一。

D12. 评测体系与商业闭环：没有 ImageNet 的世界怎么迭代

为什么重要

CV 有 ImageNet，NLP 有 GLUE/MMLU，穿戴健康没有公认的 benchmark。原因是任务定义、设备、人群、标签标准都不统一。这带来了两个后果：

  1. 你无法用一个数字证明「我的模型更好」
  2. 团队容易退回到用 engagement 指标自我安慰

要建立的三套评测

第一套：离线算法评测（要有骨气）

要素 要求
数据划分 必须按 subject 分 + 按时间分（前瞻式：用前 N 周训练，预测未来）
报告方式 Bland-Altman、MAE/MAPE/MARD、95% LoA；分类任务报告分层的 sens/spec/PPV/NPV + 校准曲线
基线对照 至少三个：规则基线、传统 ML 基线、「重复昨天的预测」的朴素基线（很多产品连这个都打不过）
分层报告 按肤色、性别、年龄、BMI、疾病状态分层。发现亚群劣化必须公开在内部报告里
外部验证 至少在一个完全独立的设备上验证

第二套：在线产品评测（要诚实）

三层指标体系已在 D7 讲过（参与层 / 代理结局层 / 临床结局层）。补充两个容易忽略的：

  • 依从性曲线（adherence curve）：用户在第几天弃用？这是产品最真实的「健康度」指标
  • 负面事件监测：有多少用户报告焦虑升高？有多少用户因为 App 而产生了不必要的就医或不必要的不就医？这类负向指标极少有人测，但它是负责任的产品标志

第三套：Agent 自身评测（这个最缺）

LLM Coach 的评测怎么做？我建议一套 rubric-based 的多维度评测集，至少包含：

维度 评判方法
医学事实正确性 由专业临床人员标注的金标准 QA 集
数字保真度 自动：LLM 输出中的所有数字是否都能溯源到结构化数据源（这个可以 100% 程序化检查，必做）
行为科学正确性 rubric：是否正确识别了用户的 TTM 阶段？干预强度是否匹配？是否推进了阶段？
不确定性与谦卑 在信息不足时是否正确弃权/提问，而非编造结论
安全合规 是否越过 medical claim 红线；是否正确处理红旗症状
共情与语气 rubric 打分或偏好pair对比
长期推进 最终指标：用户在 N 周内是否推进了行为改变阶段

关于商业闭环的两点观察

观察一：健康产品的留存死在第 21 天到 45 天之间。 这个区间的本质是「新鲜感耗尽，而健康改善尚未显现」的死亡谷（因为生理改善的时间常数是周~月级，见 D2）。唯一能穿越它的东西是「短期可见的小胜利」——不是体重的下降，而是「你完成了连续 3 天的固定睡眠时间」「你发现午饭后散步确实能让下午精神更好」这类自我效能感的即时反馈。

观察二：CGM 是这个规律的一个例外，因为它把反馈周期压缩到了分钟级。这就是为什么代谢健康赛道在过去几年增长最快。如果你能在其他维度上找到「缩短反馈周期」的代理机制，你的产品就获得了不对称优势。 例如： - 睡眠 → 次日午后精力评分（当天即可观察） - 运动 → 当晚 HRV 与深睡比例 - 饮食 → 下一餐前的饥饿感/精力（而非体重）

把延迟结果转化为即时反馈，是 AI Coach 最有价值的产品直觉之一。

6.2 必读论文清单（按主题，标注为什么读）

原理类（建立物理直觉）

  1. Allen J. Photoplethysmography and its application in clinical physiological measurement. Physiol Meas, 2007. —— PPG 的百科全书式综述，入门必读
  2. Nitzan M, et al. 关于 PPG 波形重搏切迹与血管老化的系列论文 —— 理解 PWA
  3. 关于 Beer-Lambert + 光散射修正用于脉搏血氧测量的经典推导 —— 理解为什么指端与前臂的测量条件差别那么大
  4. Moens-Korteweg / Hughes 方程与血压估算 —— 理解无袖带血压的物理上限

血压（争议最激烈，值得一读其 opposing views）

  1. Avolio A, et al. Challenges Presented by Cuffless Measurement of Blood Pressure if Adopted for Diagnosis and Treatment of Hypertension. Pulse, 2023. —— 最坚定的反对派，论证清晰
  2. 与之对应的社论 Cuffless Measurement of Blood Pressure: Not Good Enough for Diagnosis and Treatment of Hypertension (Karger) —— 读完两边才算真的懂这件事
  3. Apple HTNF 的 peer-reviewed validation paper（描述 7 项研究的开发与验证过程）—— 学习「如何诚实地做一个准确度有限但有益的产品」
  4. 2025 AHA 科学声明 / 2025 AHA-ACC 高血压指南的无袖带相关章节 —— 监管与临床团体的官方立场

睡眠

  1. Sridhar N, et al. 端到端 dilated CNN 做睡眠分期 + 迁移学习（Comput Biol Med 2023）—— 学习端到端 vs 特征工程的对照
  2. Sun H, et al. LSTM + 132 HRV 特征 + actigraphy，面向睡眠障碍人群（Sleep, 2020）—— κ=0.60 的标准参考
  3. 4 类睡眠分期的高效算法的 computationally efficient work（Sci Rep, 2023）—— κ=0.638 且快 50 倍，学习嵌入式部署权衡
  4. SleepFM（多模态 PSG 基础模型）—— 学习「一次夜间记录能预测多少疾病」的上限展示

PPG 基础模型（2025–2026 最活跃的方向）

  1. PulseOx-FM（Weizmann，medRxiv 2026）—— 学习如何用「实际年龄」作为表征质量的代理任务，以及如何做前瞻性发病预测
  2. MMR / Masked Multiscale Reconstruction（NeurIPS 2025 Workshop on Learning from Time Series for Health）—— 小波多分辨率 + 掩码重建。建议精读其对小波设计的消融分析
  3. Pulse-PPG（UbiComp / IMWUT 2025）—— 现场数据 vs 临床数据预训练的根本性争论
  4. Toward On-device Foundation Models for Raw Wearable Signals（NeurIPS 2025 Workshop）—— 端侧小卷积 FM，参数少三个数量级而性能不降
  5. PaPaGei（开源 PPG 基础模型）—— 拿来当 baseline

AI Coach / 行为干预（最重要的两块）

  1. PerMA 试验（npj Digit Med, 2026）—— N-of-1 ML + LLM 匹配人类教练方案，可作为个体化干预的产品模板
  2. My Heart Counts 2.0 design and rationale（Am J Prev Cardiol, 2026，N=15,000）—— LLM coaching 的大规模 RCT 设计，值得照着设计你自己的研究
  3. Hardeman W, et al. 行为改变轮与 COM-B 的原始文献 —— 行为科学的产品化基础
  4. Nahum-Shani I, et al. 微随机试验（MRT）与 JITAI 的方法学论文 —— 穿戴干预的实验设计圣经
  5. Klasnja P, et al. JITAI（Just-In-Time Adaptive Intervention）的框架性论文 —— 行为干预的 Agent 化表达

可靠性与评价方法

  1. Bland JM, Altman DG. Statistical methods for assessing agreement between two methods of clinical measurement. Lancet, 1986. —— 两页纸，改变你看所有「准确性对比」的方式
  2. Riemann D, et al. AASM 睡眠分期手册 —— 睡眠分期的 ground truth 定义
  3. 关于 Scoping review 的 wearable validity 综述（如 MDPI Sensors 2026 的 Consumer Smartwatch Technology in Health and Performance Research）—— 一个较新、较全面、且诚实的消费手表效度综述，适合作为「哪些指标有证据、哪些没有」的速查表

6.3 90 天学习路线

第 1–30 天：建立生理与测量的底层直觉

目标：不再把任何穿戴数字当真值。

  • [ ] 读完 PPG 综述（Allen 2007）+ SpO₂ 的 Beer-Lambert 推导
  • [ ] 手工实现一遍：从一段原始 PPG 里做出心率（带通 → 峰值 → RR → 中值）
  • [ ] 手工算一遍 RMSSD / SDNN / LF-HF，理解为什么 LF/HF 有争议
  • [ ] 读 Bland-Altman 原始论文，并给自己某款设备做一次「手表 vs 胸带」的 Bland-Altman 分析
  • [ ] 通读你自己产品的所有指标的 Metric Card，补齐「证据等级」字段
  • [ ] 读一遍 Apple 的 IRNF / ECG / HTNF 的 IFU（Instructions for Use）文件——这些是免费的、写得极严谨的工业文档，是最好的「如何诚实表述」教材

第 31–60 天：信号处理 + 经典模型

目标：能独立跑通一条链路的端到端 pipeline。

  • [ ] 用 SHHS / Sleep-EDF 跑一遍睡眠分期：先 actigraphy 基线，再特征+LSTM，再端到端 CNN
  • [ ] 用 PPG-DaLiA 复现「PPG → 活动心率」，体会到 cadence lock 是什么
  • [ ] 实现一次 ANC/LMS：把 IMU 当参考，从含噪 PPG 里滤除伪影 / 滤波
  • [ ] 实现一次个人基线 + EWMA + CUSUM 变点检测，可视化
  • [ ] 用状态空间/卡尔曼做一个「2 观测 → 1 隐状态」的最小 demo，输出置信区间
  • [ ] 重要演习：把所有数据集做一次「按 subject × 按时间」的划分，重跑一遍你之前的模型，看性能掉多少

第 61–90 天：Agent 化与实验文化

目标：让一个真正的 Health Coach Agent 跑起来并有迭代机制。

  • [ ] 设计 Metric Card schema 并注入 LLM prompt；写自动化测试检查 LLM 输出的数字是否可溯源
  • [ ] 实现「红旗三级分流」旁路（规则层，不能依赖 LLM）
  • [ ] 基于 COM-B + TTM 写一个分层对话策略库，做成 tools/技能
  • [ ] 实现 Assessment Protocol 工具箱（至少一个主动测试：深呼吸 HRV 或坐立测试）
  • [ ] 用 contextual bandit（Thompson Sampling）替换掉「固定规则推送」
  • [ ] 建立完整干预日志，跑一次 off-policy evaluation
  • [ ] 写一个 rubric-based 的 Coach 评测集（50–100 条，覆盖医学正确性、数字保真、行为科学正确性、安全合规）

B. 常见误区清单（值得贴在工位上）

❌ 误区 ✅ 事实
穿戴测得的心率是"真实心率" 是延迟的估计，且每段有自己的质量等级
HRV 低 = 压力大 HRV 是多个原因的共同结果，需要多证据汇聚才能归因
LF/HF 是"交感/副交感受平衡" 这是一个被严重过度简化的经典说法，现代方法学普遍不接受
SpO₂ 98% = 不缺氧 贫血、CO 中毒时都会假性正常
手表能测血压 通常是估算；2025 AHA/ACC 指南不建议用于诊断管理。 Apple HTNF 甚至不报数值
睡眠分期准确率 80% 意味着我的深睡数据可信 那是逐 30 秒 epoch 的 κ≈0.6；聚合量可信度更高，但单个夜里深睡 12 分钟 vs 20 分钟的区别基本是噪声
打鼾录音能诊断睡眠呼吸暂停 打鼾是 OSA 的症状，不是诊断依据；很多 OSA 患者不打鼾
汗水排得多 = 排毒效果好 汗液 99% 是水与电解质，"排毒"是营销概念
可以靠手表识别你的 7 种情绪 EDA/HR 只落在唤醒维度，没有效价分辨力
用了大模型就能做健康教练 LLM 懂健康知识，但不懂行为改变——后者才是教练的全部价值
engagement 高 = 产品对健康有益 最能拉 DAU 的手段往往致病（焦虑驱动通知、红点、损失厌恶）
随机切分数据做训练/测试没问题 会导致同一个人的相邻片段同时进 train/test，性能虚高
用了 PPG 基础模型就自动更好 先用线性探针对比「手工特征 + GBDT」baseline，否则可能是负优化

C. 一句话的心智模型（送给你）

穿戴设备给你的是影子，不是物体本身。

影子有时会骗你——但只要你知道它是什么角度投下来的、什么时候会变形、并且同时看几个不同角度的影子，你就能相当可靠地推断出物体的形状。

这就是 AI 健康教练的全部工作。
